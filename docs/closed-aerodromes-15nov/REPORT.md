## Stats box — old vs new

Tiles: AIRPORTS, INTL, CTRL, UNCTRL, ATO/DTO, DFE.

| Tile | First-paint HTML (old, hardcoded) | After JS on the old 640-card list | New (computed) |
|---|---:|---:|---:|
| AIRPORTS | 641 | 640 | **582** |
| INTL | 10 | 13 | **10** |
| CTRL | 23 | 23 | **23** |
| UNCTRL | 556 | 555 | **497** |
| ATO/DTO | 270 | 270 | **271** |
| DFE | 134 | 134 | **134** |

Why the old numbers were wrong:

- AIRPORTS 641 was a stale hardcoded first-paint value, one off the real 640-card list. UNCTRL 556 was also one off (real 555).
- After JS, INTL showed 13 and the type tiles did not add up (13 + 23 + 555 = 591, which is neither 588 aerodromes nor 640 cards). Three controlled “major” aerodromes — FAEL (King Phalo), FAGG (George), FAKM (Kimberley) — were counted in both INTL and CTRL because the runtime count (and the main-page filter) treated type `major` as international. New counts use exclusive `data-cat` only, and the filter matches that. Type chips on the cards were not changed. 10 + 23 + 497 = 530 aerodromes, plus 52 heliports = 582.
- ATO/DTO 270 was a stale hardcoded Valid count. The real Valid ATO/DTO total in `app-data` is **271** (299 records, 28 Expired). DFE 134 was already the correct Valid count (234 records, 100 Expired).
- ATO/DFE tiles were never updated at runtime. They are now painted from `WM_PUBLIC_STATS`, generated by `tools/wm-public-stats.mjs` from the Valid records. The 1.8 MB app-data file is not loaded on the main page. The stats script itself is also not loaded as an extra asset; the numbers and paint function are folded into `fv3.js` so the main-page asset count stays at 53 (budget 54).

The 58 removed cards were all uncontrolled, so INTL and CTRL are unchanged, UNCTRL drops by 58 (555 → 497), and AIRPORTS drops by 58 (640 → 582).
